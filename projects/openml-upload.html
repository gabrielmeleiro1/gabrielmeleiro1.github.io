OpenML Upload

A school project we built for Jan van Rijn at LIACS, so people can upload datasets to OpenML that don't fit the Croissant format it uses.

Pretty much the whole design follows from treating every uploaded file as untrusted until it's been scanned and a person has looked at it.

Getting files in

Datasets can run to several gigabytes, so they never pass through the API server. The browser asks for a short-lived upload link and sends the file straight into a quarantine folder in storage. Folders go up as a single ZIP along with a list of what's meant to be inside, and the server checks the two against each other, so an extra file tucked into the archive gets the whole upload rejected.

Scanning and review

Once an upload is confirmed ClamAV scans a copy of it, and clean files move over to a ready folder. Anything infected, missing or impossible to scan stays in quarantine and is never served, and if the scanner happens to be down the files just wait until it's back.

A clean scan isn't enough on its own, though. A reviewer still has to approve the file before it can be downloaded, and downloads only work for people who are signed in.

Sign-in

Sign-in goes through GitHub only, so there are no passwords to store or leak. Access tokens stay in memory and get refreshed through a cookie the frontend can't read, and when I removed the old email and password routes I added tests to make sure they don't come back.

Running it

The whole stack runs in Docker Compose, with the API, the frontend, PostgreSQL, ClamAV, Caddy and an S3-compatible store as separate services. There are 265 backend tests plus Playwright tests that click through sign-in and uploads against the real stack. After that I'd like to get it deployed on AWS, and add multipart uploads for really large archives.
