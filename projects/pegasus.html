Pegasus

C++ Limit Order Book & Matching Engine

Pegasus is a C++17 trading-systems project built around a price-time priority limit order book. The current implementation supports limit and market order matching, emits structured execution reports, exposes non-mutating depth snapshots, and includes regression tests for the matching core.

Problem

A trading engine has to maintain strict price-time priority while handling frequent inserts, cancellations, executions, and top-of-book reads. The important engineering constraint is correctness under mutation: matching must update both taker and maker orders, cancellation should not scan the whole book, and read-only depth views must not accidentally change book state.

Approach

Pegasus stores bids and asks in ordered price maps, with each price level holding orders in FIFO order. Active orders are also indexed by order id for direct lookup. Internally, price levels use fixed-point keys so floating-point price input does not create unstable map lookups.

Current Capabilities

  • Limit orders: cross immediately when prices are compatible and rest remaining quantity.
  • Market orders: consume available liquidity and never rest unfilled quantity.
  • Execution reports: each fill includes symbol, price, quantity, aggressor side, taker order id, and maker order id.
  • Depth snapshots: bid and ask level reads are non-mutating and safe for display or reporting.
  • Stop-limit scope: the enum exists, but the matching engine rejects it until trigger handling is implemented.

Regression Tests

The project now includes a regression test build script for core matching behavior. 

./build_scripts/build_tests.sh
  • Crossing limit orders match through addOrder.
  • Partially filled limit orders rest remaining quantity.
  • Market orders do not rest unfilled quantity.
  • Depth snapshot reads preserve best bid and ask state.

Simulation & Benchmarking

Pegasus also includes an ETH/USD simulation, benchmarking infrastructure, and multiple threading examples. The threading layer is designed around symbol isolation, where independent symbols can be processed in parallel while preserving strict ordering inside each symbol's book.
